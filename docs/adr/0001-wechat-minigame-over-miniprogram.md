# 采用微信「小游戏」形态，而非在「小程序」里嵌 Canvas

项目要做一个可上线的堆叠建造游戏。微信平台要求游戏内容以「小游戏」类目提审，普通小程序类目下承载游戏内容会被判类目不符。因此工程从第一行代码起就走小游戏框架（`game.json` + `game.js` + Canvas 2D 渲染），放弃小程序 `pages` 结构。

## Considered Options

- **小程序 pages + Canvas 2D**：开发结构更熟悉，加设置页/关于页很顺手，但提审必被驳回。仅适合自用。
- **先写不依赖 wx 的游戏内核，形态后定**：理论上零返工，但小游戏与小程序在渲染上下文获取、触摸事件、生命周期上的差异仍需适配层，属于为不确定性提前付费。本项目的形态已确定，不值得。

## Consequences

- 收益：唯一能合规上线的形态；改完即可上传体验版。
- 代价：个人主体上架需软著 + 工信部备案 + 游戏自审自查报告三件套；个人主体无法开通虚拟支付，变现只能走广告（IAA）。
- 代价：小游戏没有 `pages` 机制，后续若要「设置页 / 排行榜页 / 关于页」这类 UI 页，需自行用 Canvas 绘制，或使用开放数据域。这是与小程序形态最大的体验落差，会在后续决策中反复出现。
