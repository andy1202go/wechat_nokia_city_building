# 楼层是正方形，地基属于地面

原版的每层楼是一个**方块**（多方资料写「代表每一层楼的方块」，且人口算法里把每层楼的上表面积记为 1）。本工程此前是 64 × 22 的扁砖，长宽比约 2.9 : 1，玩家看到的是一根细长的「电线杆」。

同时，塔一歪，脚下的地基就跟着翘：一端扎进地面、一端翘到草地上。它压在一块**平直贯通**的地面上——地面本身没有任何问题（`drawGround` 一直是铺满全宽的一条平带），问题出在绘制顺序上：

```js
ctx.rotate(lean);                                    // ← 坐标系从这里开始倾斜
draw.fillRoundRect(ctx, foundationX, 0, ...);        // ← 地基在倾斜坐标系里画
```

地基是地面的一部分，不是塔的一部分。被画进塔的旋转里，它就成了跷跷板。

## Considered Options

### 楼层尺寸

- **同时把宽度也放大到 88（贴近原版的方块占屏比）**：舍弃。`FLOOR.width` 是容差的基准（完美 = 宽 × 0.18、失误 = 宽 × 0.5），而坍塌判据用的是 `FOUNDATION.width` 的半宽。宽度放大到 88 后，失误容差 44 会**超过一层的坍塌阈值 40.3**，两档判定的语义随即倒挂 —— 因为 `run.js` 有一条不变式：**失误的楼层不进塔**，一般落点进塔。于是偏差 43 判「一般落点」、进塔、偏心 43 > 40.3、塔倒；偏差 45 判「失误」、翻落、塔完好。「投得更歪反而更安全」。要救它必须把 `FOUNDATION.width` 从 130 同步放大到约 176，而只改高度同样达成「正方形」这个目标、代价为零。
- **只改高度、宽度保持 64（选定）**：`FLOOR.height` **不参与任何判定**，只影响塔高度量、摄像机和绘制。所以这一改对判定与全部测试零影响，难度曲线一动不动。

### 地基

- **让它跟着塔轻微摇摆，只是不随倾角旋转**：舍弃。摇摆表达的是塔的晃动，地基是地面，两者不该耦合。
- **取消独立地基，容错范围改由中线两侧的刻度表示**：舍弃。地基同时承担着「塔站在什么上面」的实感与「能站多宽」的提示，全部交给刻度会让画面失去落地的重量。
- **保留独立台基的外观，只把它钉死**：舍弃。它仍然读作「压在地面上的一块灰板」。
- **并入地面（选定）**：抽成独立的 `drawFoundation`，画在塔的**任何变换之外**；配色不再是共用的一套灰，而是各主题按自己的 `ground` 色系配的深一档。读起来变成「地面在这里换了一种铺装」。

## Consequences

- 地基**不参与塔的任何变换**（倾角 / 摇摆 / 倒塌旋转）。这条由 `tests/render.test.js` 的「地基不跟着塔一起转」钉住；它读的是 canvas 桩记录的**坐标系是否已被旋转**标记 —— 因为这件事在 `fillRect` 的入参上完全看不出来（`rotate` 改的是变换矩阵，不改变绘制参数）。写入时已验证过：把地基移回旋转坐标系，该用例立刻失败并直指病因。
- 因此 `themes.js` 的 `SHARED` 里**没有** `foundation`，三套主题各配一份。这是有意的，不是遗漏。
- `FLOOR.height` 从 22 涨到 64，让**画面里同时可见的层数从 15.4 降到 5.3**，镜头也更早开始跟随（到第 3 层，地面就出屏幕）。这不是副作用而是对齐原版 —— 原版一次也只看到 4~6 块。
- 由此带来一个真实的代价：**「地基能站多宽」只在开局那两层看得见**。塔一高，地面就出屏幕，地基中线（`drawAxis`）于是承担了更多提示责任。`dev/render-frame.js` 为此新增了 `ground` 场景（低塔 + 偏心），专门用来验地面与地基——其它场景里根本看不到它们。
- `FLOOR.width` 与 `FOUNDATION.width` 是**绑死的一对**（前者定容差、后者定判定尺度），尽管它们在 `config.js` 里隔了好几节、看起来毫无关系。这条关系现在由 `validate.js` 显式钉住：只放大楼层宽度会被拦下，并提示要同步放大地基。默认配置里这两者的余量并不宽（32 vs 40.3），下一次调尺寸很容易撞上。
- 塔身与地面的「低幼感」还有一层没解决：方块本身的圆角、均匀的 4×4 窗格网格、偏弱的明暗对比。配色是其中一项，见后续记录。
