# 塔身配色只分三档明度，形态去积木化

楼层改成正方形之后，画面立刻暴露出一个此前被形状掩盖的问题：**一摞彩虹积木**。

原来 `building` 是**六个色相循环**（白天主题：黄 `#F0C353`、蓝 `#6FA8DC`、橙 `#E0A04A`、绿 `#7FBF7F`、紫 `#B491D0`、米 `#EAE3D6`）。在 64 × 22 的扁砖上，那些色块细长，读起来还只是「彩色条纹」；方块化之后每层色块面积放大约三倍，就成了彩虹积木。

诊断是：「低幼感」不是颜色丑，而是**变化太频繁**。颜色的职责应当是**指明这是塔**，而不是**让每层都不一样的颜色**。

参照获奖休闲游戏的共通手法 —— Monument Valley（每关一个主题色 + 70-20-10 法则）、Alto's Odyssey（极简剪影 + 动态光影）—— 方向是一致的：低幼来自「多」，艺术感来自「少」。

## Considered Options

### 塔身配色

- **保留六个色相，只降饱和度**：舍弃。病灶是色相的数量，不是每个色相的鲜艳程度。降饱和度只会得到「一摞灰彩虹」，仍然花。
- **整座塔同一颜色，靠给每层加描边来分层**：舍弃。描边是线；九个楼层的描边叠起来会在塔身上织出一张网，比换色更吵。
- **同一色相，分三档明度（选定）**：色相统一让塔读作「一座楼」，明度分档让层界仍然清楚。
- **只分两档，或干脆单色**：舍弃。玩家**必须看得出哪一层偏了** —— 这是可学习性的来源。单色时只剩体积感在分层，相邻层的偏移会变得难以察觉。见 `dev/compare-palette.js` 的五版对照：单色那一版的塔形仍然成立，但层与层的界限几乎读不出来。

### 三档怎么排

- **中档取明度的算术中点，顺序排成 中 → 浅 → 深（选定）**：相邻层的明暗变成「+d、−2d、+d」的等步长上下交替，节奏均匀，读起来是一层层的楼板。
- **三档不等距，或按 浅 → 中 → 深 的顺序**：舍弃。前者会让某些层界忽然糊掉，后者会形成一个循环的明暗斜坡，读起来像塔在朝一个方向「褪色」。

另有一条上限：**最亮的一档不能亮过地平线附近的天空**。塔是前景、天空是背景，前者更亮会失去纵深。白天主题的天空下端约 0.85 明度，所以那套色板的最亮档停在 0.73 左右。

### 形态

配色只解决「花」。剩下的「积木感」来自形状本身，三处各改一点：

- **圆角 `FLOOR.radius` 3 → 2（选定）**：大圆角是积木块最明显的特征，真实建筑是方的。不能取 0，那会硬到割裂每层轮廓。
- **窗格 4 × 4 → 3 × 3，且每扇窗改成竖向长条（选定）**：4 × 4 在 64px 里塞 16 扇窗，缩小后读作一层「网格贴图」而不是立面；方窗又像乐高凸点。少而长才有建筑感 —— 竖向开窗是塔楼立面的默认语言。
- **右侧暗面 13% → 16%（选定）**：13% 读起来只是「右边有一道脏」，而不是「这栋楼有厚度」。
- **把圆角改成 0、并把明暗对比拉到最大**：舍弃。那会走向另一端的「硬像素风」，与本工程柔和的天空氛围冲突。

## Consequences

- **判定零影响。** `building`、圆角、窗格、侧墙都是纯观感参数，一个都不参与判定。这一轮改完 141 个测试全绿，没有一个用例需要改。
- **`dev/compare-palette.js` 从「一次性探索」变成了可复用的设计工具**：五版色板全部由**当前主题的色板按规则推导**（三档 / 两档 / 单色 / 三档+强调色），所以换主题也能跑。唯独「改前 · 六色相循环」是写死的 —— 它是被淘汰的那一版，留作反面教材：以后若有人觉得「每层一个颜色挺好看的」，跑一次就能看到它画到方块上是什么样子。
- **那个脚本还演示了一条不该违反的规则**：三档之外再插一个 `perfectCap` 当强调色，会立刻和 HUD 的金色连击徽章打架。**金色是玩家该独占的奖励信号，不能出现在普通楼层的色板里。**
- **主题与渲染层的接口约定：主题只给出光晕的峰值 alpha，渲染层负责衰减的形状。** 曾经天体光晕只有 0 / 0.45 / 1 三档，中档写成 `withAlpha(glow, 0.35)` —— 而那是把 alpha **设成** 0.35，与峰值 0.38 几乎相等，于是从圆心到半径的 45% 处几乎是平的，整片光晕被拉平成一顶锅盖：在深色夜空里能看出一圈清晰的硬边，读起来像聚光灯而不是月亮。现在按峰值 alpha 的比例逐级衰减（见 `draw.alphaOf` 与 `sky.js` 的 `FALLOFF`），收得快、尾巴长。
- **白天的草地原来是整幅画里最饱和的一档（`#8DD05A`）**，只有它在喊。降成鼠尾草绿之后环境安静下来，塔才成为主角。这一条不在最初的议题里，但属于同一类问题：**环境不该和主角争饱和**。
- `dev/probe-pixels.js` 是这一轮新增的工具，起因是地基与地面的几何关系不能靠看：扫一条竖列才确认了「塔底 729、地基自 730 起、地面从 730 连续铺下去」—— 贴合，既没有悬空也没有下陷。**凡是涉及「这里到底是什么颜色、分界在哪」的判断，都落到采样上。**

## 待定

- 三套主题的**取舍由用户定**；当前默认 `dusk`（黄昏，层次最强）。切换改 `js/render/themes.js` 的 `DEFAULT_THEME`。
