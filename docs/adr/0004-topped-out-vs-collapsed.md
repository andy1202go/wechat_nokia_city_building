# 终局拆成「封顶」与「坍塌」两个互斥事件

原始资料自身存在两种失败语义被混用的情况：中文资料称「累计三次失误大楼自动封顶，无法继续向上搭建」，同时又称「若建筑失去平衡倒塌则游戏结束」；英文资料则把两者合并表述为「3 次失误后塔坍塌」。再叠加本项目已选定的重心模型，终局实际上有两个独立成因。

因此拆成两个互斥的结束事件：**封顶** —— 失误额度耗尽，本局结束、塔身保留；**坍塌** —— 偏心超限，塔整体倒下。两者走不同的动画、文案与结算。

## Considered Options

- **只保留偏心超限**：删掉失误额度，最纯粹、最物理、状态最少。舍弃它的原因：丢掉原版最标志性的「3 次机会」UI，容错边界变模糊，新手不知道「我还能撑几次」，只知道塔在变歪。
- **只保留失误额度耗尽**：偏心降级为纯视觉、不参与判定。最贴近中文资料的直读。舍弃它的原因：回到「计数与视觉脱节」的问题——塔看着还稳却因计数归零而倒；且玩家没有可预测终局的观测量，只能数次数。

## Consequences

- 玩家能区分两种失败的学习信号：「我稳住了但机会用完了」与「我把楼盖倒了」。
- 代价：多一个终局状态，需要两套结算文案与两段结束动画。
- 两个事件在结局优劣上不对等——**封顶**保留塔身，**坍塌**摧毁塔身。这一差异如何折算进**得分**，属于可调参数，未在本 ADR 中锁定。
