# 塔身稳定性由重心偏心判定，而非落点偏差的累加

塔会不会倒，需要一个判定量。直觉做法是把各层楼的落点偏差取绝对值累加（`Σ|dx|`），但左右往复堆叠的塔会因此被误判：一个四层偏移为 `0 / −12 / +10 / −4` 的塔，重心实际压在轴线附近，`Σ|dx|` 却已经算到 26。玩家的物理直觉会与判定持续冲突，挫败感全部来源于此。

因此判定量取**重心偏心** `e = |重心 − 地基中心|`，超过地基半宽的比例阈值即坍塌。每层楼的绝对水平位置仍各自保留，用于渲染逐层错位的可读性；视觉倾角 `θ = atan(e / h)` 由 `e` 导出，不独立存储。落点偏差另拆**完美容差**与**失误容差**双阈值，两者之间为**一般落点**，推高偏心但不中断连击。

## Considered Options

- **累积偏移和 `Σ|dx|`**：实现最短，一行 reduce。但非物理量，判定与玩家直觉冲突（见上）。
- **刚体整体倾斜**：只存倾角 θ，整塔作为刚体旋转，视觉与判定完全同源。但楼层之间不再保留独立偏移，玩家失去「我这次偏了多少」的唯一反馈通道，学习曲线陡到没有反馈。

## Consequences

- 偏心可用 running sum 增量维护，每层 O(1)，无需遍历全塔。
- 因为 θ 是导出量而非独立状态，不存在「判定未倒但视觉看着要倒」的脱节，也无需两套状态同步。
- 代价：多引入「重心」这一概念，必须在 UI 上显性化（水准泡或轴线指示），否则玩家无法理解塔为何倒下。
- 遗留：终局条件与**失误额度**的关系尚未定案，见 `CONTEXT.md` 的 Flagged ambiguities。
