# 坍塌的倒塌演出只存在于表现层

ADR-0004 定下「坍塌**摧毁**塔身」，但落地时这一条只在文案上兑现了：实现里坍塌的全部反馈是屏幕抖动 0.48 秒、一次重震、结算面板变红——**塔身纹丝不动地站着**，只按派生倾角歪了十几度。本局最戏剧性的一刻，玩家看不到任何东西塌下来。这是文档意图与实现之间的落差，而非新的设计取舍。

因此补上一个倒塌演出：坍塌后整塔绕地基边缘翻倒，`collapseSec` 秒内倒到 `collapseSweepDeg`，然后停住。

关键约束是**它完全活在表现层**。画面上的总倾角由两部分相加而成：内核的 `leanAngle`（由偏心算出的派生量，渲染层只读）与表现层的 `collapseTilt`（纯演出量）。演出量绝不回写内核，也不被任何判定读取。

## Considered Options

- **让内核在坍塌时把倾角调大**：最省事，渲染层一行不用改。舍弃它的原因：`leanAngle` 是**派生量**而非独立状态（ADR-0003 的核心不变式），一旦允许外力改写它，倾角就与偏心脱钩，画面与判定开始各说各话。这正是 ADR-0003 否决「刚体整体倾斜」时避免的问题。
- **在内核里加一个 `collapsed` 角度字段供渲染读取**：把「倒多少」当成内核状态。舍弃它的原因：内核已经在 `end` 事件里给出了 `ending: 'collapsed'`——**信号足够，缺的是演出**。为了一个纯观感量去扩内核的状态面，等于让内核为渲染的方便买单。
- **纯表现层叠加一个演出角（选定）**：内核继续只回答「发生了什么」，表现层自己决定「看起来怎么样」。内核零改动，演出可独立调参、可整体关闭（`collapseSweepDeg: 0`）。

## Consequences

- 画面上的总倾角有两个来源，且**只有其中一部分参与判定**。这一点必须写在 `towerView.js` 的文件头与参数手册里，否则未来的读者会把演出角误当成物理量，进而「顺手」拿它去做判定或调平衡。
- 倒塌必须绕**倾倒那一侧的地基边缘**旋转，不能绕中线。绕中线会让塔身一角沉到地面以下，看起来像整座塔陷进地里而不是倒下去。这条几何契约由 `tests/render.test.js` 的「倾倒侧底角不会扎进地面」钉住——该断言从绘制调用里反读出枢轴位置，改回绕中线即失败。
- 这是本工程唯一一处**画面动得比物理多**的地方，属刻意的表现夸张。它不产生任何可被玩家利用的信息差：坍塌已是终局，演出期间不接受输入。
- 参数化的代价是多两个观感参数（`VISUAL.collapseSec` / `VISUAL.collapseSweepDeg`）。按本项目的约定，它们必须有真实行为，否则会被死配置检查报出来。
