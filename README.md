# 摩天叠楼师

一款致敬诺基亚时代内置游戏《都市摩天楼》（Digital Chocolate《Tower Bloxx》/《City Bloxx》）的**微信小游戏**。吊车在塔顶上方摆动，掐准时机松手，把楼层一层层叠上去——偏一点就歪，歪多了就倒。

- **只做快速模式**：一次局面建一座塔，直到坍塌或封顶
- **零外部素材**：美术全部用 Canvas 图元绘制，音效全部用 Web Audio 程序合成。没有一张图片、没有一个音频文件，因此没有素材版权风险，包体也几乎为零
- **内核零 `wx` 依赖**：全部游戏规则在 `js/core/` 里，纯 Node 可测。`node tests/run-tests.js` 直接跑，不需要 `npm install`

> 玩法机制可以照搬（思想与操作方法不受著作权保护），但名称与美术素材必须重做——这是本项目的立项前提，理由见 `docs/adr/0002`。

## 快速开始

### 在微信开发者工具里运行

1. 打开微信开发者工具，选择 **小游戏** 项目类型
2. 目录选择本工程根目录
3. `project.config.json` 里已经设好 `"compileType": "game"`
4. AppID 目前是占位的 `touristappid`，**正式开发与上传必须换成你自己的小游戏 AppID**

> ⚠️ 不要用「小程序」类型打开本工程。游戏内容用小程序 `pages` 承载会被判**类目不符**驳回，这是本项目选择小游戏形态的直接原因（见 `docs/adr/0001`）。

### 在浏览器里快速试玩（不需要开发者工具）

```bash
node dev/serve.js          # 默认 8777 端口，可用 node dev/serve.js 9000 改
```

打开 `http://localhost:8777/` 即可玩。手机上连同一局域网访问终端里打印的地址，能真触摸 + 真震动。

`dev/` 是一个**浏览器运行壳**：把工程唯一依赖的 6 个 `wx.*` 能力映射到标准 Web API，再用一个极简 CommonJS 运行时装上工程自己的 `require`，跑的是**同一份 `js/` 代码**。页面右侧带状态面板（帧率/楼层/相位/机会/连击/人口/得分/结局），方便调参时盯数。

用途是**缩短调参回路**：改 `js/core/config.js` → 点「重载页面」即可看到新手感，不必等开发者工具。

| 局限 | 说明 |
|---|---|
| 只用于本地试玩 | `dev/` 已在 `project.config.json` 的 `packOptions.ignore` 里，不会进小游戏包 |
| 手感不等于真机 | 桌面鼠标与手指的触感有差异，**最终手感必须以真机为准** |
| 不含微信特有能力 | 分享、订阅消息、开放数据域等不在壳的范围内 |

> 壳的路径引用与依赖图由 `tests/dev-server.test.js` 守住——这类问题一旦出现是**静默白屏**（`<script>` 加载失败既不触发 `window.onerror` 也不抛异常），搭壳时就真的踩到过一次。

### 跑测试

```bash
node tests/run-tests.js
```

零依赖、不需要 `npm install`。退出码 0 表示全部通过。

当前 **139 个用例**，覆盖：

| 套件 | 覆盖内容 |
|---|---|
| `config` | 参数自检能否抓出自相矛盾的配置；防死配置的静态检查 |
| `tower` | 重心模型、坍塌阈值、倾角派生、摇摆衰减 |
| `crane` | 钟摆几何、正弦位置、摆角反解、下落积分 |
| `judge` | 完美/一般/失误三档判定与边界 |
| `combo` | 连击规则（完美递增、一般保持、失误清零） |
| `run` | 局面状态机、两个终局、事件队列、得分折算 |
| `render` | 视口换算、表现层动画（含坍塌倒塌演出）、**整条渲染链的烟囱测试**、HUD 布点与命中 |
| `game` | **编排层端到端**：启动、触摸、暂停、终局、重开、音效、震动、长帧钳制 |
| `dev` | **预览壳**：资源路径不 404、依赖图能解析、加载器与服务器约定一致、`dev/` 不进包 |

> 渲染层依赖 Canvas，原本在 Node 下不可测。`tests/canvas-stub.js` 给 Canvas / WebAudio / wx 打了桩，把整条渲染与编排链真实跑起来，重点是抓 **NaN 坐标**（在真实 Canvas 里是静默不绘制，肉眼只能看到"某块东西不见了"）和 **save/restore 不配对**。

### 分层纪律

```
core    决定「发生了什么」 —— 确定性、可测试，不知道 Canvas 的存在
render  只读内核状态，决定「看起来怎么样」
audio   消费内核事件，决定「听起来怎么样」
game    只做编排与输入分发，不含游戏规则、也不含绘制细节
```

**判定与动画完全解耦**：`run.landAt(run, x)` 是判定与全部状态变更的唯一入口，单元测试直接调用它，不需要跑动画。事件通过队列单向流向渲染与音效层。

## 调参

全部参数集中在 `js/core/config.js`。改完请跑 `node tests/run-tests.js` —— 参数自检会拦下**逻辑上自相矛盾**的配置（这类问题在开发者工具里不报错，只表现为"手感很怪"）。

推荐的调参回路：**开着 `node dev/serve.js`**，改一个参数 → 浏览器点「重载页面」→ 立刻看手感；定下来之后再跑一次测试，确认没有破坏自检约束。

逐参数的详细说明、派生量速查表、常见目标配方、必须成对修改的组合，见 **[`docs/参数调优手册.md`](docs/参数调优手册.md)**。

一条铁律：`TOLERANCE.missRatio` 必须等于 `0.5`，它等价于"落点中心越过下层支承边缘"的物理临界点。要放宽容错请改 `FOUNDATION.width`。

## 上线前的准备

> 以下为立项时（2026-09）的了解，**提交前请以微信官方最新要求为准**。

- **形态**：小游戏（`compileType: "game"`）。小程序形态无法承载游戏内容
- **AppID**：把 `project.config.json` 里的 `touristappid` 换成正式小游戏 AppID
- **类目资质**：按小游戏类目提交，备齐所需材料
- **版权材料**：本工程零外部素材，但名称与玩法复刻的性质仍建议准备**游戏自审自查报告**
- **软著**：纯免费、无内购的小游戏可走免版号通道，但仍需软件著作权登记，**办理周期以月计，名称需先定**
- **个人主体限制**：个人主体无法开通虚拟支付。本项目无内购，不受影响
- **iOS 注意**：iOS 端虚拟商品不能使用微信支付。本项目无虚拟商品
